## Frozen filter and evaluation

The primary filter keeps an argument only when a nonempty, contiguous, **verbatim quote occurs within a turn of the reported actual speaker**, the annotation says it supports this particular claim, and attribution is correct. A rebuttal must also answer its paired reason. All required judgments must be `yes`. `uncertain` is rejected by this strict primary policy and counted separately. No quote is accepted by matching across speaker turns. `should_keep` is the independent holistic evidence-validity judgment used to measure false rejection/acceptance, rather than a way to choose a policy by role-label accuracy.

Use the human instructions in [HUMAN-TASKS.md](HUMAN-TASKS.md). Compare a collected checker with both humans using:

```sh
python scripts/clean_quote_study.py agreement \
  --first work/clean_quote_study/annotator_1_completed.csv \
  --second work/clean_quote_study/annotator_2_completed.csv \
  --predictions results/clean_quote_study/pilot/model_annotations.jsonl \
  --out results/clean_quote_study/human_agreement.json
```

The agreement report exposes completion, three-valued and binary agreement, Cohen's three-valued kappa where defined, uncertain-pair counts, disagreements and checker false acceptances/rejections against each human separately. It rejects a shared annotator ID and proxy/model provenance. Both worksheets must cover the frozen packet, and immutable claim/side/kind/transcript fields are checked against the canonical bank before agreement or inference. Checker predictions must match the same claim and transcript hash. A partial pilot is compared only where its predictions overlap the human sample, with explicit coverage counts. Distinct IDs attest, but cannot technically prove, that two actual people worked independently. No blank or proxy worksheet satisfies the human gate.

Paired inference is available only after supplying valid annotations for **all 48 arguments of every included snippet**:

```sh
python scripts/clean_quote_study.py evaluate \
  --annotations results/clean_quote_study/pilot/model_annotations.jsonl \
  --source model --out results/clean_quote_study/pilot/evaluation
```

Use `--source human` only for completed human evidence annotations, not model outputs. The 96-row stratified worksheet is an evidence-audit sample, and cannot itself produce a complete 150-snippet filter comparison. No automatic extension of its labels to unsampled arguments occurs.

Filtering is the sole change in the primary pair: the clean transcript, argument text, scores, all relation scores, pinned rules, conditional optimization and tie policy remain fixed. The shared `post_audit_evaluation.py` evaluator preserves the original dropped-XOR behavior when an endpoint is removed; a surviving rebuttal with no reason contributes a constant. Ties within `1e-9` objective units select A. If no reason survives, the explicit route is the historical default A. Infeasible conditional objectives are exported as JSON `null` plus `infeasible_sides`, rather than a nonstandard infinity.

Outputs include paired per-snippet objectives and predictions, accuracy, class recall, balanced accuracy when both classes exist, argument retention by kind, uncertainty counts, decision routes, paired meeting-bootstrap intervals and evaluation runtime. Small pilots have very few clusters and support only a feasibility observation. Collection usage and provider-reported cost live in the separate collection manifest. The required simple baselines and full-bank role/direct results are in the companion post-audit evaluation; a new filtered full-bank analysis must preserve the same baseline population. No threshold, uncertainty policy, checker capacity or practical effect target is selected from final role accuracy. Before genuinely new confirmation, lock a meaningful improvement and desired precision/power; neither was retroactively invented here.

## Bounded collection

The command below defaults to **dry run**, never reads or prints a key in that mode, and selects snippet IDs from the deterministic human-audit sample order. Set `--ids` for an explicit comma-separated pilot. An executable OpenAI-compatible HTTPS provider and exact model ID must be supplied by the user/coordinator.

```sh
python scripts/clean_quote_study.py collect \
  --model EXACT_PROVIDER_MODEL --base-url https://PROVIDER/v1 \
  --api-key-env PROVIDER_API_KEY --max-requests 4 --max-cost-usd 0.25 \
  --out results/clean_quote_study/pilot
```

Add `--execute` to make requests. Each snippet is one request covering its 48 fixed arguments; `--max-requests` bounds total attempted snippets with no retry loop. The provider must return a complete JSON annotation list with exactly the requested IDs and valid speaker-bound quotes. Invalid or truncated answers stop immediately and are **not cached or accepted**; previously accepted progress survives. Their usage/cost is recorded before validation, and exact failed responses are quarantined in ignored `work/clean_quote_study/quarantine/`, separate from reusable caches. Valid exact requests/responses are cached in ignored `work/clean_quote_study/quote_cache/` by request hash, including endpoint/model/prompt/settings. To preserve prior evidence, actual collection refuses an output directory already containing a collection manifest; use a new output directory to revalidate/reuse caches. The public manifest records request hashes, response IDs, exact served model, usage, wall time and reported cost where available. Secrets and raw HTTP error bodies are omitted. The cost cap stops before another request after the reported cumulative cost reaches its limit; a single response can cross the cap, and missing provider cost cannot be bounded by dollars. The request count is the hard bound. Model outputs remain explicitly `annotator_type=model` and cannot replace independent validation.

The first coordinator-run pilot accepted 48 model annotations for snippet112, then fail-stopped on invalid snippet4; snippets54/56 were not attempted. The accepted snippet's filter-off and filter-on decisions were both correct. This one-case observation does not establish filter effectiveness. Its recorded USD0.00209833 covers only the accepted response: the initial implementation failed to retain usage for the invalid billed response, whose exact cost is unavailable, so the original total is a **lower bound**. Subsequent code records failed-response usage before validation; the original evidence is preserved rather than retroactively filled.

## Fresh-data feasibility

The actual archives contain 75 meetings and 60 transcript participants. The current 150 snippets use 45 meetings and 22 same-span participants; expanded ±60 contexts expose 30 participants. There are 30 unused meetings and 30 participants unseen in the expanded contexts. Seven participants have the corpus education label `Professor`; four occur in the current data. The three additional professors (`fe041`, `fn043`, `me032`) occur only in **Buw001**. Its only other unseen participant is `me908`, who lacks an education label. Thus there is **no new professor plus independently known new nonprofessor focal pair** in the available unused meetings. Changing window length cannot fix that participant-level absence.

The deterministic eligibility scan nevertheless exports 16 fresh-meeting exploratory windows: 30 consecutive segments, at least 100 words, exactly one professor in the window, a known nonprofessor, at least three segments per focal person, fixed 15-segment start grid, and one selected window per meeting. No window shares a meeting with the existing snippets, and selected source segment intervals cannot overlap. Professor-disjoint Buw001 windows are exported separately with shared nonprofessor/context membership explicit; they come from a single meeting and support a narrow exploratory extension only. The all-speaker-disjoint file is empty, as the actual eligibility scan found none.

Independent evidence judgments and a genuinely fresh, independently labeled speaker-disjoint test corpus remain blockers for a confirmatory conclusion. Acquiring another corpus or new consenting, labeled participants is the next data task. A late split of the old 151 examples is never relabeled as fresh confirmation.
